# Проверки

Исходники 0.3.0-poco, 8 сентября 2026 года.

## Выполнено локально

Команда `python3 tools/test.py`, JDK 21, целевой Java API тестов 17:

| Набор | Проверок | Покрытие |
| --- | ---: | --- |
| HourlySelectionTest | 27 610 | Стабильность по часу и seed, цикл, границы long, размеры набора |
| WallpaperImportPolicyTest | 56 | Отдельный, общий, собственный, живой и неизвестный фон; новый фон внутри часа; отсутствие цикла; ограничение декодирования; прерванная запись |
| RefreshTaskTest | 8 | Раннее назначение, очередь, отказ выполнения и завершение обработчика |
| LockWallpaperControllerTest | 35 | Реальный контроллер с тестовыми заменами Android: запись и удаление, смена фона во время рендера/перед записью, отказ разрешения/сохранения, журнал и восстановление |

Manifest проверен как XML. Это JVM-проверки, а не Android-инструментальные или e2e-тесты.
Тестовые классы из tests/controller не входят в сборку приложения. Поведение Android
API, Bitmap, AlarmManager, JobScheduler и HyperOS этими заменами не подтверждается.

`python3 tools/check_android.py --sdk ...` компилирует ресурсы, весь Java-код приложения
и DEX на SDK 35 / Build Tools 35.0.1 без создания ключа или релизного APK.
Фактический результат этой проверки смотрите в CI соответствующего коммита;
само наличие команды не означает успешную сборку. Релиз 0.3 здесь не объявлен.

## Проверить на устройстве

Ни один сценарий ниже пока не выполнен на физическом POCO или эмуляторе.
Записать версию APK, Android/HyperOS, лаунчер, поставщика обоев, разрешения,
время назначенного и фактического запуска. Не открывать приложение перед проверкой
фона: открытие само запускает обновление. В интерфейсе сохраняется время последнего
alarm отдельно от открытий приложения; подробности и ошибки находятся в preferences.

| Сценарий | Ожидаемый результат |
| --- | --- |
| Первый запуск, разрешение и отказ чтения текущего фона | Нет фотодиалога/синего фона. Без доступа старые/встроенные обои не подставляются; отказ объяснён. |
| Два реальных часовых перехода, экран выключен, не на зарядке | Приходят независимые запуски; оба экрана показывают ожидаемый кандзи; измерить задержки. |
| Выгрузка процесса без force-stop; Doze | Обновление приходит через систему. Зафиксировать задержки и длительность записи. |
| Только блокировка, домашнего виджета нет; отзыв точного доступа | Recovery остаётся зарегистрирован и после доставки восстанавливает неточный alarm; задержки не ограничены 30 минутами. |
| Перезагрузка и первое разблокирование; обновление APK | Восстанавливается расписание. Старый ключ сохранён для обновления APK. |
| Ручная смена статичной блокировки, включая тот же час | На новом фоне текущий кандзи, автосмена не выключается. Старый фон не возвращается. |
| Ручная смена при выгруженном процессе | Новый фон подхватывается при ближайшем системном запуске, не обязательно мгновенно. |
| Несколько быстрых смен фона, смена во время рендера | Обнаруженная гонка отменяет старую запись. Проверить оставшуюся неатомарную гонку платформы. |
| Смена только домашнего фона при отдельной блокировке | Домашний фон не переносится на блокировку. |
| Общий статичный фон | Читается общий источник, запись только FLAG_LOCK. Проверить кадрирование и переход к отдельной блокировке. |
| Живые обои, ID 0/ошибка API, тема или карусель | Обои не заменяются, доступное объяснение; виджет продолжает работать. Тему и карусель проверить отдельно. |
| Отзыв доступа к файлам, затем новый фон | Проверенный собственный фон может обновляться из копии; новый фон остаётся нетронутым до выдачи доступа. |
| Собственное событие смены обоев | Нет бесконечного цикла setBitmap и второго кандзи поверх первого. |
| Отключение после внешней замены фона | Автосмена останавливается, внешний фон сохраняется. |
| Прерывание между setBitmap и сохранением ID | Не импортируется изображение с возможным старым кандзи; показано требование установить фон заново. |
| Установка поверх 0.2: собственное фото, старый однотонный режим, потерянная копия | Фото использует проверенный чистый источник; без источника требуется новый фон в Android, никакой автоматической подстановки. |

Исторические результаты 0.2 (сборка и подпись APK, 41 проверка прежней политики)
доступны в истории Git. Они не подтверждают сборку или работу версии 0.3.
